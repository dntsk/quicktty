# QuickTTY 0.1.2 Release Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Выпустить QuickTTY `0.1.2` build `9` как подписанный, нотарифицированный stable arm64 DMG с рабочим Sparkle appcast и сделать его GitHub `latest`.

**Architecture:** Текущий tested beta-код не меняется; release preparation синхронно переводит metadata и guarded pipeline с `0.1.2.beta-2` build 8 на stable label `0.1.2` build 9. Exact release commit проходит единственный clean pre-deploy gate, после чего pipeline собирает, подписывает, нотарифицирует и staples DMG, создаёт appcast только из final DMG, а GitHub Release сначала проверяется как draft и только затем публикуется как `latest`.

**Tech Stack:** Swift 6, AppKit, XcodeGen, POSIX shell, Sparkle 2, Developer ID, Apple notarytool, GitHub CLI.

**Step 3: Проверить final artifact и appcast**

Run:

```sh
DMG=.build/Release/QuickTTY-0.1.2-arm64.dmg
APPCAST=.build/Release/appcast/appcast.xml
stat -f '%z' "$DMG"
shasum -a 256 "$DMG"
grep 'enclosure' "$APPCAST"
```

Expected: enclosure URL указывает на `v0.1.2/QuickTTY-0.1.2-arm64.dmg`, length равен `stat`, signature присутствует.

### Task 6: Создать и проверить immutable GitHub Release

**Files:**
- Use: `docs/releases/0.1.2.md`
- Publish: final DMG and appcast only

**Step 1: Создать annotated tag**

Run:

```sh
git tag -a v0.1.2 HEAD -m 'QuickTTY 0.1.2'
git push origin v0.1.2
```

Expected: tag указывает на exact gated release commit.

**Step 2: Создать draft с обоими assets**

Run:

```sh
gh release create v0.1.2 \
  .build/Release/QuickTTY-0.1.2-arm64.dmg \
  .build/Release/appcast/appcast.xml \
  --draft --verify-tag --title 'QuickTTY 0.1.2' \
  --notes-file docs/releases/0.1.2.md
```

Expected: draft содержит ровно `QuickTTY-0.1.2-arm64.dmg` и `appcast.xml`.

**Step 3: Проверить draft до публикации**

Через GitHub API/CLI проверить draft flag, tag target, exact asset names, DMG size/SHA-256 и exact final appcast bytes/enclosure. При несовпадении удалить только draft и остановиться; не публиковать и не изменять assets существующих releases.

**Step 4: Опубликовать stable latest**

Run:

```sh
gh release edit v0.1.2 --draft=false --latest
```

Expected: release public, не prerelease, `latest` указывает на `v0.1.2`.
