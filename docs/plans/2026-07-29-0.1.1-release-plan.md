# QuickTTY 0.1.1 Release Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Выпустить QuickTTY 0.1.1 как подписанный, нотарифицированный arm64 DMG и публичный GitHub release.

**Architecture:** Версия должна быть одинаковой в XcodeGen metadata, именах release-артефактов и контрактах pipeline. Релиз создаётся только после clean pre-deploy на запушенном release commit; notarized DMG публикуется неизменяемым asset под tag `v0.1.1`.

**Tech Stack:** Swift/AppKit, XcodeGen, shell release scripts, Developer ID, Apple notarytool, GitHub CLI.

---

### Task 1: Синхронизировать metadata и release-контракты

**Files:**
- Modify: `project.yml`
- Modify: `scripts/release-helpers.sh`
- Modify: `scripts/build-release.sh`
- Modify: `README.md`
- Modify: `scripts/tests/build-release-test.sh`
- Modify: `scripts/tests/notarize-dmg-test.sh`
- Modify: связанные утверждения release-contract, найденные поиском

**Step 1: Обновить ожидаемую версию**

Установить marketing/release version `0.1.1`, следующий монотонный `CFBundleVersion`, и соответствующие DMG/stage/notarization имена. Обновить документацию без изменения release API.

**Step 2: Проверить контракты**

Run: `make release-contract && make notarize-contract && make lint`
Expected: release и notarization contracts проходят с `0.1.1`.

### Task 2: Проверить релизный набор и оформить commit

**Files:**
- Add/Modify: текущий native-search diff, version metadata и project memory

**Step 1: Выполнить полный gate**

Run: `make check && git diff --check`
Expected: все contracts, format lint, build и tests проходят; в diff нет whitespace errors.

**Step 2: Создать release commit и отправить его**

Run: `git add ... && git commit -m "release: 0.1.1" && git push origin master`
Expected: чистый `master`, `HEAD == origin/master`.

**Step 3: Выполнить clean pre-deploy**

Run: `.agents/scripts/pre-deploy-check.sh`
Expected: clean tree, upstream совпадает и повторный `make check` проходит.

### Task 3: Собрать и нотарифицировать DMG

**Files:**
- Generate: `.build/Release/QuickTTY-0.1.1-arm64.dmg`
- Generate: `.build/Release/QuickTTY-0.1.1-arm64.dmg.notary-result.json`

**Step 1: Выполнить signed release**

Run: `make signed-release` с установленными в окружении Developer ID identity, Team ID и Keychain notary profile.
Expected: DMG подписан c hardened runtime и accepted Apple, затем stapled и проверен Gatekeeper.

**Step 2: Зафиксировать hash и proof**

Run: `shasum -a 256 .build/Release/QuickTTY-0.1.1-arm64.dmg`
Expected: выводит final notarized artifact digest.

### Task 4: Опубликовать immutable GitHub release

**Files:**
- Modify: `.agents/memory/tasks-completed.md`
- Create: `.agents/memory/handoffs/2026-07-29-0.1.1-release.md`

**Step 1: Создать annotated tag и GitHub release**

Run: `git tag -a v0.1.1 ... && git push origin v0.1.1 && gh release create v0.1.1 ...`
Expected: один неизменяемый DMG asset опубликован на GitHub.

**Step 2: Проверить опубликованный asset**

Сверить размер и SHA-256 публично скачанного DMG с локальным notarized artifact.

**Step 3: Сохранить release evidence**

Добавить в project memory только release tag, artifact path, digest, notarization status и выполненные gates; не записывать credentials.
